## TTS correctness — accepted

Goal 0005 fixed the Goal 0004 defects.

### Active backend / voice resynchronization

`should_sync_tts_after_reader_command` now treats both:

- `tts_backend`;
- `windows_voice_id`

as runtime-resynchronizing TTS changes.

Regression tests demonstrate that an active backend or voice switch:

- preserves the canonical current sentence;
- updates the configured backend/voice;
- cancels/replaces the old request instead of silently continuing stale synthesis/playback state.

### Effective Windows voice identity

When the Windows backend is initialized:

- a configured voice ID is validated/resolved;
- no configured voice ID resolves `SpeechSynthesizer::DefaultVoice`;
- the resolved effective voice ID is retained by the engine;
- synthesis and cache identity use that same effective voice.

This removes the ambiguous `windows:default` cache behavior for normal engine use.

### Piper isolation

Piper eSpeak path sanitization and `PIPER_ESPEAKNG_DATA_DIRECTORY` setup now run only for `TtsBackend::Piper`.

Windows TTS no longer depends on Piper initialization.

### Windows WAV evidence

The Windows integration probe now:

- enumerates voices;
- resolves the default voice;
- verifies missing configured voice IDs are actionable;
- synthesizes a fixed sentence;
- verifies nontrivial output;
- opens the result with the shared Rodio `Decoder`;
- verifies channels, sample rate, and nonzero duration.

Authoritative Windows run `34150175084` exposed uncaptured evidence:

## Goal watcher — accepted concept, corrected protocol

Goal 0005 added:

- `scripts/codex-goal-notify.ps1`;
- `scripts/test-codex-goal-notify.ps1`;
- detached watcher startup during Goal 0005.

The report states that Goal 0005 used a checkout-safe sentinel:

`.git/lanternleaf-goal-state/0005.terminal`

and launched the watcher detached.

### Director finding 1 — slugged goal filenames

The initial watcher directly checked:

- `docs/work/done/<id>.md`;
- `docs/work/blocked/<id>.md`.

Real goal filenames are slugged, for example:

`0005-tts-correctness-and-goal-notify.md`

So future goals could reach `done/` or `blocked/` while the watcher failed to notice the terminal file.

### Director finding 2 — notification should mean “reviewable”

A local `done/` transition can occur before the terminal implementation branch is pushed.

For the human workflow, the most useful semantic is:

> when the desktop notification appears, the branch/report is already pushed and ChatGPT can inspect it.

Therefore terminal notification should be explicitly **post-push**.

### Director correction

Before Goal 0006:

- watcher repository fallback recognizes both exact and slugged goal filenames;
- the normal trigger is the checkout-safe `.git/lanternleaf-goal-state/<id>.terminal` sentinel;
- new `scripts/signal-codex-goal-terminal.ps1` atomically writes that sentinel after terminal push;
- the signal helper waits briefly for watcher acknowledgment;
- missing toast/ack remains non-fatal;
- checkout restoration occurs after signaling;
- Windows CI tests watcher/signal behavior.

The fallback path remains diagnostic/test support; normal Codex protocol uses the post-push sentinel.

## Workflow result

No separate watcher command is required from the human.
