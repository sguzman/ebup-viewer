## Accepted TTS architecture

The implementation preserves the director-owned flow:

`canonical sentence -> selected synthesis backend -> cached WAV -> shared Rodio/Sonic playback -> canonical session progression`

Accepted properties:

- Piper remains the default backend.
- Windows uses WinRT `SpeechSynthesizer`.
- Windows voice descriptors expose stable IDs/display names/languages.
- Windows sentence output is persisted as WAV.
- Rodio/Sonic remain shared rather than duplicated into a Windows playback state machine.
- config/session/runtime expose backend and Windows voice selection.
- voice catalog enumeration is user-triggered/cached in app state rather than called every frame.
- blank voice input is normalized to `None`, so blank means Windows default voice.

## Correctness defect 1 — active backend/voice switch does not resync

`patch_has_tts_fields` correctly recognizes:

- `tts_backend`;
- `windows_voice_id`.

However `should_sync_tts_after_reader_command` only resynchronizes on:

- font size;
- lines per page;
- pause-after-sentence;
- speed;
- volume.

It omits backend and voice.

Therefore a backend/voice patch can update canonical config while an already-running request continues using the old engine/backend.

This directly contradicts Goal 0004 D2.

Goal 0005 must add backend/voice to the active resync decision and regression-test request replacement/rebuild semantics.

## Correctness defect 2 — implicit default voice cache identity is unstable

Current Windows cache identity is:

`windows:<configured-id>`

or:

`windows:default`

when no ID is configured.

But actual synthesis with no ID uses whatever Windows currently considers the default voice.

If the OS default changes, `windows:default` remains unchanged and old sentence WAVs may be reused for a different effective voice.

Goal 0005 must resolve the actual default voice identity and use that stable voice ID in cache identity.

## Additional hardening

### Piper initialization leakage

`TtsEngine::new` currently sanitizes eSpeak and may set `PIPER_ESPEAKNG_DATA_DIRECTORY` regardless of selected backend.

That initialization belongs only to Piper.

Goal 0005 should isolate it.

### Backend-neutral error strings

The runtime still emits `Failed to initialize Piper TTS engine` even when the selected backend may be Windows.

Make diagnostics backend-neutral or backend-specific based on actual selection.

### WAV verification

The Windows integration test currently proves a file larger than a WAV header is produced.

The shared runtime subsequently decodes files with Rodio, but the dedicated probe does not explicitly assert decodeability.

Goal 0005 must make the probe decode the synthesized file through the same decoder assumptions used by shared playback.

### Hosted voice evidence

The Windows test prints voice count, but ordinary passing Cargo tests capture stdout.

Add a targeted `--nocapture` CI step or equivalent so the report can distinguish:

- hosted runner had voices and synthesized;
- hosted runner had no usable voices and only exercised enumeration.

## UI modularity

Goal 0004 added Windows TTS settings/catalog state directly in the already-large egui `app/mod.rs`.

The addition is bounded, but future work should extract Windows TTS settings/catalog helpers into a coherent module rather than continue growing the god file.

Goal 0005 may perform only the small extraction necessary for its TTS correctness/UI work.
