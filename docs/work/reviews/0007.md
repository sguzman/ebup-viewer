# Goal 0007 Director Review — Workflow Superseded

## Decision

The Goal 0007 implementation was technically correct: CI successfully built and validated a self-contained Windows QA artifact.

However, after integration the human rejected the artifact download/extract/run path because it added unnecessary friction and created a second coordination/distribution surface outside the repository.

That feedback changes the workflow requirement.

## Superseding rule

Ordinary development and manual QA stay in the repository checkout.

Canonical Windows human workflow:

```powershell
git pull
.\qa.ps1
```

Repository-owned dependency contract:

```powershell
.\deps.ps1
```

`qa.ps1` automatically invokes the dependency contract unless explicitly skipped.

## Dependency ownership

The repository now owns installation/checking for:

- Rust/rustup and the MSVC Rust target;
- Visual Studio 2022 C++ build tools;
- CMake;
- Pandoc.

The human no longer needs to remember a Visual Studio Developer PowerShell ritual; `scripts/windows-dev-env.ps1` enters the MSVC environment programmatically.

## Artifact policy

The downloadable `lanternleaf-windows-qa` artifact is not part of the ordinary workflow.

The active QA-bundle CI job and bundle-specific scripts are removed to avoid maintaining two human execution paths.

CI artifacts may be reintroduced later for releases, debugging, or fallback distribution if they solve a real problem. They must not displace the repo as the normal collaboration surface.

## Why PowerShell instead of Nix/mise

For the current Windows dependency surface, a checked-in idempotent PowerShell bootstrap is the smallest reliable mechanism because the hardest dependency is the Visual Studio C++ workload itself.

Nix/mise can be reconsidered if LanternLeaf develops a larger cross-platform toolchain matrix. Introducing them now would add another environment abstraction without eliminating the Windows-native MSVC installer.

## Gate 2

Automated parity remains accepted.

Real-desktop signoff remains pending and should now be performed from the repository with `.\qa.ps1`.
