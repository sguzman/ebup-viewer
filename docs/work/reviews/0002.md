for the core test binary.

The report's local `--test-threads=1` result of 158 passed / 9 failed is not sufficient to declare test isolation complete.

### Additional failure 1-2: cache roundtrip races

These tests fail only in the normal parallel run:

- `cache::tests::pdf_sync_meta_roundtrip_preserves_geometry_mode_and_strategy`
- `cache::tests::pdf_sync_meta_roundtrip_preserves_runtime_policy`

Both write metadata and then fail to load it.

The cache test module contains `cache_root_uses_env_override_when_present`, which mutates the process-wide `LANTERNLEAF_CACHE_DIR` variable while other tests call `cache_root()`.

That creates a plausible and direct process-global race: a write can resolve under one cache root and the immediately-following read under another.

Goal 0002 explicitly required eliminating environment/test races, so this remains baseline work.

### Additional failure 3: Windows fixture newline drift

`epub_loader::tests::text_source_falls_back_without_markdown` receives:

```text
Plain text source fixture.\r\n
```

on Windows while the assertion expects:

```text
Plain text source fixture.\n
```

This is cross-platform fixture determinism, not a product PDF defect.

### Additional failure 4: cross-column OCR alignment

`session::tests::pdf_ocr_alignment_artifact_populates_token_lineage_and_cross_column_contract` fails only in the normal parallel Windows run in the reviewed evidence.

It persists and reloads cache-owned PDF sentence/alignment artifacts, so cache-root/process-state leakage must be ruled out before classifying it as a genuine PDF algorithm defect.
