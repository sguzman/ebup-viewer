## Finding 1 — search parity is overstated

The matrix claims:

`Search next/previous/selected result = verified automated`

for all four formats.

The new real-session test only issues:

`SearchSetQuery`

and checks that matches are non-empty.

It does not exercise:

- search next;
- search previous;
- selected-result movement/identity.

### Required correction

For representative real sessions, exercise the actual session commands for:

- set query;
- next match;
- previous match.

Assert that the selected result changes deterministically and maps to the expected canonical sentence/page position.

Update the matrix to reflect exactly what is proven.

## Finding 2 — canonical-text cleanliness is claimed but not asserted

The report says the tests verify syntax-clean canonical text, but the shown contract only proves:

- canonical sentences exist;
- sentence splitting is internally consistent.

It does not explicitly reject representative source noise.

### Required correction

Add source-family-specific assertions, using the representative fixtures:

### Markdown

Assert canonical speech text does not contain representative raw syntax such as:

- heading markers;
- emphasis delimiters;
- raw link/image syntax;
- list markers where the canonicalizer is expected to remove them.

Do not write brittle global assertions that reject legitimate punctuation.

### HTML

Assert canonical speech text does not expose:

- HTML tags;
- script/style content;
- representative attributes/markup tokens.

### EPUB

Assert canonical speech text does not expose:

- XHTML/XML tags;
- package/chapter markup tokens.

If current production behavior fails these expectations, fix the bounded canonicalization defect rather than weakening the assertion.

## Finding 3 — pretty projection / anchor evidence is too shallow

Goal 0006 explicitly required current Rust-native pretty projection evidence for Markdown / HTML / EPUB.

The first pass checks:

- `PrettyKind`;
- sentence-anchor-map cardinality;
- presentation toggle preservation.

It does not actually inspect representative pretty structures or test mapping quality.

### Required correction

Use the current Rust-native pretty/block helpers and representative fixtures to prove supported structures are present/readable.

At minimum cover the structures that current production code claims to support from the fixtures:

- heading;
- paragraph;
- emphasis;
- list;
- link;
- image;
- HTML table/secondary block where current model supports it.

For sentence-to-pretty mapping, test:

- at least one exact/strong mapping;
- at least one deterministic bounded fallback when exact mapping is unavailable, if the current model exposes such a path;
- no unrelated/random block selection;
- presentation toggle preserves canonical/search state.

Do not invent support for structures the model genuinely degrades. Mark those as degraded in the matrix with evidence.

## Finding 4 — auto-scroll / jump semantics are not newly proven

The matrix claims deterministic mapping logic is automated for Markdown/HTML/EPUB, but the Goal 0006 diff adds no obvious targeted auto-scroll/jump decision test.

### Required correction

Locate the current pure decision logic used to decide active-sentence jump/scroll behavior.

Add deterministic tests where feasible for:

- new active sentence triggers a jump;
- same sentence does not repeatedly retrigger jitter;
- mapping/fallback strength affects jump behavior as intended.

If the logic is inseparable from egui and cannot be tested without GUI state, document the exact seam and mark the matrix **manual verification required** instead of **verified automated**. Do not claim automation that does not exist.

## Finding 5 — TTS runtime parity covers only TXT/Markdown

The authorized goal states:

> Use the simulated TTS runtime with sessions loaded from the real representative fixtures.

and asks for each format to cover a meaningful subset.

The first pass only loads:

- `representative.txt`;
- `representative.md`

into `TtsRuntime`.

HTML/EPUB are not exercised through the simulated runtime.

### Required correction

On Pandoc-capable hosted Windows:

- load representative HTML real session;
- load deterministic EPUB real session;
- run them through simulated `TtsRuntime`.

For all four formats, cover a sensible common subset including at least:

- PlayFromPageStart;
- PlayFromHighlight;
- SeekNext;
- SeekPrev;
- RepeatSentence;
- Stop/cancellation.

Assert:

- canonical cursor remains in range;
- active sentence text agrees with canonical cursor where exposed;
- stale cancellation cannot mutate the replacement request/cursor;
- backend setting changes do not fork reader index semantics.

You may parameterize this instead of duplicating tests.

### Required correction

Where HTML/EPUB assets have special cleanup behavior, verify that bounded contract or mark remaining manual asset cleanup explicitly.

## Finding 7 — Windows source -> synthesis acceptance needs explicit disposition

Goal 0006 acceptance gate 13 requires either:

- a representative source -> session -> Windows synthesis -> decode probe; or
- a report explanation for why the existing generic Windows synthesis probe adds equivalent evidence and the extra path would not materially improve it.

The first report does not clearly make that determination.

### Required correction

Preferred: add a Windows-only integration probe that:

1. loads a representative non-PDF source through the real loader/session path;
2. obtains one canonical sentence;
3. synthesizes it through the Windows backend;
4. decodes the WAV.

TXT is sufficient for this contract; the goal is to connect **source/session canonical ownership** to actual Windows synthesis without requiring Pandoc or physical audio.

If you choose not to add it, the report must make a concrete technical case for why it is redundant.
