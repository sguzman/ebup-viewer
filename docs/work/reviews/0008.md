## Post-acceptance real-desktop hotfix — automatic catalog load

The first real desktop run after Goal 0008 acceptance exposed a workflow defect not covered by the provider tests: the native starter shell rendered an empty library and did **not** issue `LoadCalibreBooks` until the human pressed Refresh manually.

The Caliberate service itself was already running; the app simply never requested the catalog during native startup.

- native starter startup now dispatches:
  - `Bootstrap`;
  - `RefreshRecents { limit: None }`;
  - `LoadCalibreBooks { force_refresh: false }`;
- a regression test asserts the startup command set includes the automatic library load;
- `qa.ps1` now stages `conf/calibre.toml` into the isolated QA config and explicitly sets `CALIBRE_CONFIG_PATH`, removing reliance on current-working-directory config discovery.

Windows native CI for the hotfix passed dependency setup, QA preparation, workspace check/build/test, and Windows TTS.
