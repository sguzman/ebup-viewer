# Goal 0008 report — Caliberate service integration

## Result

Implemented and validated first-class Caliberate HTTP/JSON v1 support behind the existing native Rust library browser. The legacy Calibre content-server path remains available through an explicit provider boundary. All acceptance criteria passed; the goal is ready for director review/integration.

## Provider Boundary

Added `CalibreProvider::{Caliberate, Calibre}` to `CalibreConfig`, with Caliberate as the new default and `http://127.0.0.1:8181` as the default service target. Existing configuration files without a provider remain compatible: legacy URLs containing a library fragment infer the legacy Calibre provider. Catalog, materialization, authentication, thumbnails, and cache identity dispatch through the provider boundary.

## Caliberate Catalog Mapping

Added the v1 `/api/v1/books` adapter. It maps IDs, titles, authors, publication years, primary formats, and supported format metadata into the existing `CalibreBook` model. Unsupported rows are skipped; supported formats use deterministic extension priority and fall back to `primary_format` when needed.

## Pagination

Requests use bounded pages (`offset`, `limit=500`, title ascending sort) and continue until the reported total/items are exhausted. Cancellation is checked before page requests and while mapping rows.

## Content Materialization

Supported content is fetched from `/api/v1/books/{id}/content/{format}`. Bytes are written to a provider-specific temporary file, flushed, and atomically renamed into the existing download cache. Caliberate content is isolated under the `caliberate` download-cache namespace.

## Authentication

Caliberate API keys are sent only as `x-api-key` headers. Legacy Basic authentication remains limited to the legacy Calibre provider. API keys and passwords are excluded from diagnostics and cache identity.

## Legacy Calibre Compatibility

The existing `/interface-data/books-init` catalog and `/get/{FORMAT}/{id}/{library_id}` materialization routes remain intact behind the Calibre provider. Legacy config loading and Basic authentication are covered by regression tests.

## Thumbnail Behavior

Caliberate never probes legacy `get/thumb/{id}` or `get/cover/{id}` routes. Local sidecars and embedded EPUB covers remain available. Provider identity is included in thumbnail cache scope.

## Cache / Persistence

Catalog cache identity now includes provider identity, preventing Caliberate and legacy catalogs from colliding. Thumbnail and content cache scopes are likewise provider-isolated. No persistence format migration was introduced.

## Diagnostics

Catalog diagnostics identify provider, base URL, page offsets, and counts without logging secrets. Unreachable Caliberate services return explicit actionable errors naming Caliberate and the requested endpoint context.
