## Review finding: launch smoke is a false positive

The Windows workflow currently accepts either:

1. the native process remaining alive for eight seconds; or
2. the native process exiting early with code 0.

That is insufficient for a GUI launch smoke.

The code also currently does:

```rust
let _ = eframe::run_native(...);
```

so an `eframe::run_native` startup error can be discarded and converted into a clean process exit.

Therefore the Goal 0001 statement that Windows CI proved native GUI startup is **not accepted**. CI proved that the binary can be produced and invoked. It did not prove that the egui window became operational.
