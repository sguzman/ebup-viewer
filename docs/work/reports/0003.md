## Native Launch Evidence

Windows workflow run [34137162603](https://github.com/sguzman/lantern-leaf/actions/runs/34137162603) proved that checkout, MSVC setup, Pandoc setup, workspace check, and workspace build pass. Its launch smoke exited with code 1.

Run [34137948626](https://github.com/sguzman/lantern-leaf/actions/runs/34137948626) added stdout/stderr capture and reproduced the same result with the actionable error:

`egui_glow requires opengl 2.0+`

The log also shows `Starting LanternLeaf egui shell` and the eframe event-loop error, so this is a real native startup/rendering capability failure, not the former false-positive exit behavior. Workspace tests were correctly not run after the required smoke failed.

A bounded follow-up tried eframe 0.26.2's opt-in WGPU backend on run [34140187608](https://github.com/sguzman/lantern-leaf/actions/runs/34140187608). That backend also reached the native event path but reported `NoSuitableAdapterFound`; the runner exposed only an unusable OpenGL/GLES 1.1 context and no usable Vulkan/WGPU adapter. The dependency/backend experiment was reverted from the final branch because it did not provide verified runner support or justify changing the shipped renderer.
