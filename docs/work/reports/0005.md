# Goal 0005 — TTS correctness closure and goal notifications

## Result

Goal 0005 closes the reviewed Goal 0004 correctness gaps and adds the repository-owned detached Windows goal watcher. Active backend/voice changes now rebuild TTS from canonical reader state, Windows cache identity uses the effective voice ID, Piper setup is backend-specific, Windows WAV output is decoded through Rodio, and hosted CI exposes speech evidence.

## Goal Notification Watcher

Added `scripts/codex-goal-notify.ps1` and deterministic `scripts/test-codex-goal-notify.ps1`. The watcher supports done/blocked states, active/ready polling, malformed state handling, test mode, exactly-once acknowledgments, non-fatal toast failure, and an audible Windows notification request. The tests passed with `codex-goal-notify tests passed`.

## Watcher Reliability / Checkout Restoration

Goal 0005 watcher was launched detached on Windows before continuing implementation: PID 38468, using the repository script and a hidden `pwsh` process. It watches `.git/lanternleaf-goal-state/0005.terminal` as a checkout-safe terminal sentinel in addition to `docs/work/done` and `docs/work/blocked`. The terminal sentinel is written before checkout restoration, so moving the shared checkout to `main` cannot erase the state before acknowledgment.

## Backend Resynchronization

`should_sync_tts_after_reader_command` now includes backend and Windows voice patches. Regression tests prove backend and voice changes while simulated playback is active preserve the current sentence and emit cancellation/replacement behavior; unrelated idle settings do not trigger TTS resynchronization.

## Windows Voice Identity / Cache

Windows engine initialization resolves a configured voice ID or calls `SpeechSynthesizer::DefaultVoice` to obtain the actual effective ID. The resolved ID is used both for `SetVoice` synthesis and the sentence cache identity. Cache tests prove distinct backend/effective-voice identities cannot collide.

## Piper Isolation

Piper eSpeak path sanitization and `PIPER_ESPEAKNG_DATA_DIRECTORY` setup now run only for `TtsBackend::Piper`. Windows initialization does not depend on Piper environment setup. Runtime initialization/playback errors identify the selected backend instead of hardcoding Piper.

## Windows WAV Decode Evidence

The Windows-only probe now resolves the default voice, checks missing configured voice IDs remain actionable, synthesizes a sentence, verifies nontrivial output, opens it with the shared Rodio `Decoder`, and checks channels, sample rate, and nonzero duration. Local Windows and hosted Windows probes both synthesized successfully.
