### Rejection reasons

The implementation did not complete the required ownership/hot-path refactor:

1. persistence still calls full `ReaderSession::snapshot()`;
2. TTS worker command/plan/progress paths still call full `ReaderSession::snapshot()`;
3. TTS events omit the snapshot only after that heavyweight snapshot was already constructed;
4. normal reader effects and TTS runtime still own separate `ReaderSession` values;
5. TTS session synchronization occurs only on source-path change, so normal reader cursor changes and TTS cursor changes can diverge;
6. the 10,488-sentence test proves fast queue submission and snapshot-free events, but does not prove snapshot-free worker execution.

The A5.1 continuation in the reopened goal requires one canonical shared ReaderSession handle, lightweight TTS/persistence projections, zero full snapshots in hot paths, and deterministic cursor-authority regressions.

No human QA until A5.1 is implemented, reviewed, and integrated.

## Post-acceptance real-desktop hotfix — automatic catalog load

The first real desktop run after Goal 0008 acceptance exposed a workflow defect not covered by the provider tests: the native starter shell rendered an empty library and did **not** issue `LoadCalibreBooks` until the human pressed Refresh manually.

The Caliberate service itself was already running; the app simply never requested the catalog during native startup.

Hotfix:

- native starter startup now dispatches:
  - `Bootstrap`;
  - `RefreshRecents { limit: None }`;
  - `LoadCalibreBooks { force_refresh: false }`;
- a regression test asserts the startup command set includes the automatic library load;
- `qa.ps1` now stages `conf/calibre.toml` into the isolated QA config and explicitly sets `CALIBRE_CONFIG_PATH`, removing reliance on current-working-directory config discovery.

Windows native CI for the hotfix passed dependency setup, QA preparation, workspace check/build/test, and Windows TTS.

Real-desktop Caliberate catalog population remains the next human verification.
