# Goal 0006 — Non-PDF reader parity

## Result

Implemented the authorized non-PDF parity evidence pass for TXT, Markdown, HTML, and EPUB. The work adds a deterministic representative corpus, real loader/session contract tests, simulated TTS runtime coverage, QA matrix/checklist documentation, and the required hosted Windows validation. No production rendering architecture was changed and no PDF, DOCX, browser, or Calibre scope was added.

## Parity Matrix

The maintained matrix is [docs/qa/non-pdf-reader-parity.md](../../qa/non-pdf-reader-parity.md). It records source loading, canonical text, sentence/page accounting, anchors, search/navigation, text-only toggles, persistence, and TTS evidence separately for each supported non-PDF kind.

## Representative Corpus

The checked-in corpus is:

- `tests/fixtures/source-ingestion/representative.txt`
- `tests/fixtures/source-ingestion/representative.md`
- `tests/fixtures/source-ingestion/representative.html`

The integration test also builds a deterministic minimal EPUB in a temporary directory, including a navigation document, package metadata, two XHTML chapters, and stable repeated search text. The builder is exercised through `epub::doc::EpubDoc` and the real reader loader.

## Source / Session Contracts

`crates/lanternleaf-core/tests/non_pdf_parity.rs` loads representative sources through `ReaderSession::load_session_for_source`, rather than testing a mock parser. Hosted Windows runs execute the HTML and EPUB paths with Pandoc installed; the local machine lacks Pandoc, so those two paths are intentionally skipped locally. TXT and Markdown pass locally and in hosted validation.

The tests verify source kind, non-empty canonical sentences, sentence/page accounting, anchor cardinality, syntax-clean canonical text, and stable search content. They also verify persistence, reopen, and idempotent cache cleanup for the exercised sessions.

## Reader Interactions

The real-session tests cover search, search match navigation, sentence click/highlight, play-from-highlight, and text-only toggling while preserving canonical sentences and the current audio cursor. Existing core session coverage supplies next/previous/repeat and page-navigation behavior. Interactive GUI execution remains in the manual Windows checklist.

## Pretty Projection / Anchor Mapping

The parity evidence uses the Rust-native pretty projection and anchor/session mapping already owned by the core reader. It verifies pretty-kind classification, sentence/page alignment, and anchor lengths for the representative non-PDF sessions. No WebView or browser-owned production rendering was introduced.

## TTS Runtime Parity

`crates/lanternleaf-app/tests/non_pdf_tts_runtime.rs` runs the real TXT/Markdown reader sessions through the backend-neutral `TtsRuntime` with simulated progress, checks canonical cursor bounds, and verifies cancellation after play-from-highlight. Hosted workspace tests additionally exercise the HTML/EPUB session contracts and the Windows TTS probe.

## Persistence / Reopen

Representative sessions are persisted, reopened, checked for bookmark continuity, and cleaned from the cache. Deletion is asserted idempotent. The broader existing persistence suite remains part of the hosted workspace test gate.

## Windows Validation

Authoritative hosted run `34156072747` passed its `native-workspace` job, including workspace check, workspace build, all workspace tests, and the Windows TTS probe with Pandoc and MSVC configured. The local full-workspace check could not complete because this machine lacks the MSVC C/C++ compiler; the local environment also lacks Pandoc. Windows runtime claims are therefore based only on the hosted Windows evidence.

The separate hosted renderer capability probe was not required for this goal’s native reader acceptance and was still running when the native gate completed.
